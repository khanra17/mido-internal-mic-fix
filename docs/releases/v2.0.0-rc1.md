# v2.0.0-rc1 — Experimental AudioRelay microphone input

**PRE-RELEASE for explicitly requested install/reboot testing. Not a stable or
validated native-microphone release. Native autostart is ENABLED.**

## Known risk

An earlier native capture-only test coincided with an Android `system_server`
SIGSEGV in ART/JIT garbage collection. The stack does not establish causation.
Native remote delivery, boot behavior, Telegram, active-recording fallback,
full-duplex streaming and battery/RAM behavior are still unverified. Host/CI tests
are NOT proof of those results. Keep KernelSU safe mode and v1.0.0 rollback ready.

## Post-install update

The user confirmed disconnected upper-mic input and connected remote Gboard input
on the installed rc1. **Simultaneous mido Apps server + mic-receiver mode echoed the
incoming mic back to the working phone. Do not use that full-duplex mode yet.**
Stopping the server coincided with a new system_server UBSAN abort in Binder
wake-lock release (not the earlier ART/JIT trace). Cause remains unresolved. The
controller exited on service death, so reconnecting the receiver alone cannot
restore remote routing afterward. Isolated call and recovery tests are pending.

## Changes

- Preserves the original verified upper-mic mixer repair and module ID.
- Adds a small C++ control daemon; no LSPosed, app/framework hooks, JVM, APK,
  perpetual shell supervisor or periodic receiver-activity polling.
- Only AudioRelay UID + MEDIA usage is diverted to a private incoming route.
  Mido's mixed playback/caller output is never used as the substituted microphone.
- PCM transport remains native inside audioserver; no competing root AudioRecord.
- Exact virtual-mic input is advertised only after successful patch creation.
- Receiver mix START/STOP requests remote input/upper-mic fallback. This detects
  player activity, not network connectivity; edge cases need device validation.
- Idle state releases the transport patch rather than processing silence forever.
- Private ABI checks reject unverified framework/library versions.
- Cleanup errors propagate; uninstall waits for graceful shutdown. ELF packaging
  validates AArch64 executable headers and preserves binary bytes.

## Install and test

1. Download the ZIP and `.zip.sha256` asset below. Install ZIP in **KernelSU Manager**
   and reboot. No recovery flash or kernel-image replacement is involved.
   Same module ID means **in-place update is supported**. If removing the old
   module first, reboot after removal, then install rc1 and reboot again.
2. First verify the upper mic with AudioRelay disconnected.
3. On the WORKING PHONE select **microphone capture**, NOT mixed/device playback.
   On MIDO keep AudioRelay **Exclusive audio → Deactivated (Play during phone calls)**.
   Connect mido's receiver; reconnect once if it was playing before daemon startup.
4. Keep mido quiet and test Gboard speaking into the working phone. Then test
   Telegram to a separate recipient, disconnect/reconnect during recording/call,
   and simultaneous outgoing playback streaming, one test at a time.
5. Report results and `/data/adb/modules/mido_internal_mic_fix/relay.log` for failures.

Only the tested mido / qassa Android 10 vendor + framework/library ABI is supported.
Do not bypass guards. No prototype files are needed on the device; all earlier
prototype artifacts/processes/policies were removed before publishing this build.

## Rollback

If Android/audio is unstable, disable/remove this module in KernelSU and reboot;
use KernelSU safe mode if needed. Reinstall stable v1.0.0 for upper-mic-only use.
Alternatively set `RELAY_ENABLED=0` in the installed module's `relay.conf` and
reboot to disable only the experimental controller. Do not relax SELinux/privacy
or restart global audio services as a workaround.
